1) Overall assessment

The repo has a solid i18n foundation (shared catalogs, locale normalization, renderer/main preload hooks), but it is not yet production-grade for multilingual consistency because multiple user-visible flows still bypass localization and fallback behavior can leak raw keys/raw backend errors. This is especially visible in command/status messaging and Electron-returned errors.
2) Missing i18n coverage by module/page
A) Command UX + command logs (renderer)

    Title: Command results are partially hardcoded (Turkish + fixed locale timestamps)

    File: src/js/modules/commands/utils.ts

    Severity: High

    Confidence: High

    Why it matters: Command panel/log streams are user-facing; hardcoded language breaks locale consistency.

    Exact problem: toLocaleString("tr-TR"), "Başarılı", "Hata", "çalıştı" are hardcoded in runtime messages.

    Exact fix direction: Route all visible message fragments through AppI18n.t(...) and derive timestamp locale from current app language (same pattern used by modules already using resolveIntlLocale).

B) Window + screenshot command handlers

    Title: Restart/screenshot user messages bypass i18n

    Files: src/js/modules/commands/window-commands.ts, src/js/modules/commands/screenshot-commands.ts

    Severity: High

    Confidence: High

    Why it matters: These appear in command results/toasts and can leak mixed language.

    Exact problem: Hardcoded Turkish and fixed-locale timestamp remain in return payloads and logs ("Uygulama yeniden başlatılıyor...", "Screenshot alınamadı", toLocaleString("tr-TR")).

    Exact fix direction: Add translation keys for all user-facing command outcome strings and replace literals with AppI18n.t(...).

C) Electron device/whisper/server command return messages

    Title: Main-process error/status payloads are hardcoded and language-mixed

    Files: electron/device-manager.ts, electron/whisper-manager.ts, electron/server-commands.ts

    Severity: Critical

    Confidence: High

    Why it matters: These payloads flow to renderer and are shown to users; they bypass i18n control.

    Exact problem: Hardcoded strings returned directly ("Device actions supported on Linux only", "key missing", "text missing", "xclip not installed", "Account ID gerekli", "Undefined command", "restart requested", etc.).

    Exact fix direction: Return { errorKey, errorParams } or localized message from main consistently via a shared Electron translator.

3) Hardcoded user-facing strings by file
D) Assistant/slot initial labels in HTML

    Title: Static fallback labels are hardcoded in templates

    Files: src/pages/assistant.html, src/pages/entrance.html

    Severity: Medium

    Confidence: High

    Why it matters: Initial render before translation hydration can show untranslated text.

    Exact problem: Literal "Assistant", "AI1", and "-" are embedded directly in DOM.

    Exact fix direction: Replace these with i18n attributes or empty placeholders that are always filled by i18n bootstrap.

E) Preload fallback strings are hardcoded English

    Title: Preload fallback messages ignore selected locale in failure paths

    File: electron/preload.cjs

    Severity: High

    Confidence: High

    Why it matters: Early boot failures are exactly where users notice language mismatch.

    Exact problem: English-only fallback dictionary is hardcoded and used when catalog unavailable.

    Exact fix direction: Keep locale-specific fallback packs (at least EN/TR) or ship minimal bundled preload catalog independent of IPC load success.

4) Inconsistent key usage / duplicate key patterns
F) Key strategy is not fully centralized at code level

    Title: Multiple i18n resolver styles increase inconsistency risk

    Files: src/js/app/shell-i18n.ts, src/js/pages/entrance/i18n.ts, src/js/pages/opencode-ui/i18n.ts

    Severity: Medium

    Confidence: High

    Why it matters: Mixed prefixes (shell.*, entrance.*, opencodeUi.*) increase accidental wrong-key usage and hard-to-find leaks.

    Exact problem: Each module resolves keys differently (different prefixes and attribute conventions).

    Exact fix direction: Add shared typed key helpers or a central key registry per namespace, then enforce via lint rule/codemod.

G) Duplicate semantics across keys (near-duplicate vocabulary)

    Title: Same UI concepts repeated under many keys/namespaces

    File: shared/languages/en/index.json

    Severity: Low

    Confidence: Medium

    Why it matters: Raises maintenance cost and drift risk across modules.

    Exact problem: Similar concepts exist in multiple branches (e.g., logs/init states and repeated status labels), rather than shared reusable key blocks.

    Exact fix direction: Introduce a shared status/common subtree and reference consistently from modules.

5) Fallback and language-sync risks
H) Missing key fallback returns raw key string

    Title: Key-leak fallback can surface internal key paths in UI

    File: shared/i18n/catalog.ts

    Severity: Critical

    Confidence: High

    Why it matters: Production users may see namespace.key.path text instead of readable UI.

    Exact problem: translateCatalog(...) returns key when lookup fails.

    Exact fix direction: Return localized generic fallback text and log missing-key telemetry; optionally append diagnostic only in dev mode.

I) IPC error mapping permits raw backend text passthrough

    Title: Renderer accepts unlocalized backend errors as final UI string

    File: src/js/modules/ipc-errors.ts

    Severity: Critical

    Confidence: High

    Why it matters: Any Electron error message (English/Turkish/system) can leak directly to end users.

    Exact problem: If errorKey missing, raw payload.error is returned untouched.

    Exact fix direction: Require errorKey contract for user-visible flows; fallback raw message should be wrapped in localized generic error template.

J) Preload locale sync is one-shot

    Title: Preload language state may drift after runtime language change

    File: electron/preload.cjs

    Severity: High

    Confidence: Medium

    Why it matters: Language can become inconsistent across renderer/preload-generated messages in the same session.

    Exact problem: syncPreloadLocale() runs at startup, no observable re-sync hook on language changes.

    Exact fix direction: Add a language-change IPC event and re-run preload catalog sync reactively.

6) Production-critical multilingual issues (must-fix first)

    Raw key leakage fallback (translateCatalog -> return key).

    Raw backend error passthrough in IPC error resolver.

    Hardcoded Electron return messages crossing renderer boundary.

    Hardcoded command UX strings in renderer (Turkish/fixed locale).

7) Recommended cleanup plan (priority order)

    Enforce IPC localization contract (P0): all user-visible IPC failures must carry errorKey/errorParams; renderer should not show raw error.

    Replace hardcoded command/UI literals (P0): start with commands/*, device-manager, whisper-manager, server-commands.

    Harden fallback behavior (P1): no raw key display in production; generic localized fallback + telemetry.

    Add preload live locale sync (P1): react to language changes after boot.

    Normalize key strategy (P2): central typed key helpers and namespace linting; reduce duplicate semantic keys.

    Hydration-safe templates (P2): remove hardcoded initial labels in HTML where possible.
