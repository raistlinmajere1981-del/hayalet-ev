# Logging & Observability Consistency Audit (Hayalet-ev + MCP)

Date: 2026-03-12  
Scope: Main Hayalet-ev app (renderer/electron/preload/shared) + MCP server  
Excluded: `ghost-agent` (intentionally omitted)

## 1) Overall logging/observability assessment

Current implementation has strong building blocks (structured JSONL in Electron, translated log keys in many renderer paths, correlation IDs in selected flows), but it is **not yet production-grade** for incident reconstruction across app + MCP. The biggest blockers are:

- naming/path drift (`logs/app` vs documented `logs/hayalet-ev`),
- mixed/legacy logging stacks co-existing in the same codebase,
- asymmetric slot instrumentation (AI0 vs AI1/AI2),
- multiple silent failure paths (`catch {}` / ignored errors),
- inconsistent severity semantics (recoverable paths logged as error, hard failures downgraded to debug/warn),
- weak cross-system correlation model between renderer ↔ electron ↔ preload ↔ MCP.

## 2) Critical blind spots

### Finding 1 — Log root mismatch breaks app-scoped observability contract
- **File path(s):**
  - `electron/logger/core/SessionManager.ts`
  - `electron/logger/session-manager.ts`
  - `src/mcp-server/tools/log/integration.ts`
  - `electron/paths.ts`
- **Severity:** Critical
- **Confidence:** High
- **Why it matters:** Session discovery and tooling can read/write from different roots; investigators may miss logs or compare wrong sessions.
- **Exact issue:** Main app logger and MCP log integration still use `logs/app`, while project contract defines `logs/hayalet-ev` for main app. MCP integration helper also hardcodes `logs/app` when reading Electron logs.
- **Exact fix direction:** Introduce one canonical app-id map (`hayalet-ev`, `mcp-server`) and route all read/write helpers through it. Add compatibility read fallback from legacy `logs/app` with explicit deprecation warning and migration script.

### Finding 2 — Two session-manager implementations create schema drift
- **File path(s):**
  - `electron/logger/core/SessionManager.ts`
  - `electron/logger/session-manager.ts`
- **Severity:** High
- **Confidence:** High
- **Why it matters:** Different metadata filenames (`session-metadata.json` vs `meta.json`) and summary behavior create brittle tooling and partial reports.
- **Exact issue:** New logger core and legacy session-manager both exist and are operationally similar but not fully aligned.
- **Exact fix direction:** Consolidate to one session manager and one session schema. Keep a small legacy-reader adapter only in log tools.

### Finding 3 — Asynchronous file append in MCP logger is not awaited (loss risk)
- **File path(s):**
  - `src/mcp-server/utils/mcp-logger.ts`
- **Severity:** High
- **Confidence:** High
- **Why it matters:** Process exits/crashes can drop trailing lifecycle logs; incident timelines become incomplete.
- **Exact issue:** `appendFile(..., callback)` is called twice and function returns without awaiting completion.
- **Exact fix direction:** Use `fs/promises.appendFile` with `await`, or queue writes through a bounded async writer with flush-on-shutdown.

### Finding 4 — Retry/timeout/cleanup observability is inconsistent and partially silent
- **File path(s):**
  - `src/js/modules/webview/conversation-syncer.ts`
  - `src/js/modules/traffic-manager.ts`
  - `src/js/modules/relay/base-relay.ts`
- **Severity:** High
- **Confidence:** High
- **Why it matters:** Production debugging needs explicit traces of retries, fallback triggers, and cleanup outcomes.
- **Exact issue:** Several error paths are swallowed (`catch {}`), while some retry timers/state resets happen without structured logs.
- **Exact fix direction:** Add structured events for retry scheduled/executed/exhausted, timeout hit, cleanup success/fail; ban empty catch blocks in critical async flows.

### Finding 5 — Preload telemetry hooks swallow most failures
- **File path(s):**
  - `electron/webview-preload.cjs`
- **Severity:** High
- **Confidence:** High
- **Why it matters:** Webview bridge / token telemetry / provider setup failures become invisible or only visible as noisy console text.
- **Exact issue:** Many nested `catch (_) {}` blocks in provider setup, filter injection, fetch/xhr wrapping, and host telemetry send.
- **Exact fix direction:** Emit minimal structured failure events (`channel`, `slot`, `providerId`, `phase`, `error`) to host via `sendToHost` and ingest in Electron logger.

## 3) Slot symmetry analysis (ai0/ai1/ai2)

### Finding 6 — AI0 webview lifecycle logging is materially thinner than AI1/AI2
- **File path(s):**
  - `src/js/pages/assistant/webview-bindings.ts`
  - `src/js/pages/entrance/webview-panel.ts`
- **Severity:** High
- **Confidence:** High
- **Why it matters:** Similar slot operations should produce comparable telemetry to reconstruct cross-slot behavior.
- **Exact issue:** AI1/AI2 register rich `did-start-loading`, `did-stop-loading`, `did-fail-load`, `console-message`, and IPC handling logs; AI0 binding mostly updates UI state without equivalent structured logging.
- **Exact fix direction:** Extract a shared slot lifecycle instrumentation module and apply to ai0/ai1/ai2 with uniform event taxonomy.

### Finding 7 — Similar events use different context shapes by slot/module
- **File path(s):**
  - `src/js/pages/entrance/webview-panel.ts`
  - `src/js/modules/webview/conversation-syncer.ts`
  - `src/js/modules/relay/base-relay.ts`
- **Severity:** Medium
- **Confidence:** High
- **Why it matters:** Querying logs by `slot/provider/session` is unreliable when key names differ.
- **Exact issue:** Mix of `provider`, `slot`, `slotId`, `source`, `relayType`, `sessionId` without strict schema.
- **Exact fix direction:** Define canonical context contract: `{slot, providerId, runtimeSource, sessionId, conversationId, correlationId, operation, phase}` and enforce through typed log helpers.

### Finding 8 — AI0 sync path differs functionally and observability-wise
- **File path(s):**
  - `src/js/modules/webview/conversation-syncer.ts`
- **Severity:** Medium
- **Confidence:** Medium
- **Why it matters:** Debugging relay and assistant workflows needs parity between "full conversation" and "latest message" modes.
- **Exact issue:** `syncConversation` delegates AI0 to `syncLatestMessage`; this path has fewer branch logs and reduced state/retry traces.
- **Exact fix direction:** Add explicit `syncMode` field (`latest|full`) and keep equivalent lifecycle checkpoints and error markers.

## 4) Multilingual/log visibility analysis

### Finding 9 — User-visible and developer logs are not strongly separated
- **File path(s):**
  - `src/js/modules/logger/Logger.ts`
  - `src/js/pages/entrance/webview-panel.ts`
- **Severity:** Medium
- **Confidence:** High
- **Why it matters:** Production observability requires stable machine-readable messages, while UI should remain localized.
- **Exact issue:** Same log pipeline carries translated UI text and technical diagnostics; some slots route webview console noise into user-facing logger categories.
- **Exact fix direction:** Split channels into `user_status` (localized, visibility-gated) and `diagnostic` (stable English keys + params). Keep `messageKey` mandatory for UI-facing events.

### Finding 10 — Preload fallback text is English-only and can leak into UI-side streams
- **File path(s):**
  - `electron/webview-preload.cjs`
- **Severity:** Medium
- **Confidence:** High
- **Why it matters:** Mixed-language logs reduce operator clarity and harm localization quality when surfaced.
- **Exact issue:** Fallback message table is English and used extensively when catalog resolution fails.
- **Exact fix direction:** Keep developer fallback in stable internal form (key+params) and defer localized rendering to renderer/electron i18n layer.

### Finding 11 — MCP logger localizes core lifecycle messages (unstable for ops parsing)
- **File path(s):**
  - `src/mcp-server/utils/mcp-logger.ts`
- **Severity:** Medium
- **Confidence:** High
- **Why it matters:** Centralized observability systems prefer stable event keys over localized sentences.
- **Exact issue:** MCP log messages are translated at write-time; same event text differs by locale.
- **Exact fix direction:** Persist stable `eventKey` + params + locale separately; render localized text only in UI or tool output.

## 5) Hayalet-ev vs MCP logging consistency analysis

### Finding 12 — Severity semantics differ between app and MCP for similar lifecycle events
- **File path(s):**
  - `src/js/modules/logger/Logger.ts`
  - `src/mcp-server/utils/mcp-logger.ts`
  - `src/js/pages/entrance/webview-panel.ts`
- **Severity:** Medium
- **Confidence:** Medium
- **Why it matters:** Cross-app incident dashboards depend on consistent meaning of `info/warn/error/debug`.
- **Exact issue:** App frequently uses `error` for webview console-level events; MCP uses only `info` for start/success and `error` for failures with little `warn` semantics.
- **Exact fix direction:** Define severity policy matrix by event class (lifecycle, recoverable anomaly, retry, terminal failure) and codify in shared docs + helper APIs.

### Finding 13 — Correlation metadata is partial and not propagated end-to-end
- **File path(s):**
  - `src/js/modules/logger/Logger.ts`
  - `electron/logger/core/LoggerCore.ts`
  - `src/mcp-server/utils/mcp-logger.ts`
- **Severity:** High
- **Confidence:** High
- **Why it matters:** Without consistent IDs, root-cause timeline across renderer/electron/MCP is fragmented.
- **Exact issue:** Renderer supports correlationId for operations, Electron forwards it if present, MCP keeps separate `agentContext` but no guaranteed shared trace key.
- **Exact fix direction:** Introduce `traceId` + `spanId` contract and propagate via IPC, relay payloads, and MCP tool context; enforce in write helpers.

### Finding 14 — Legacy MCP integration API still points to old app label/defaults
- **File path(s):**
  - `src/mcp-server/tools/log/integration.ts`
  - `src/mcp-server/tools/log-tools.ts`
- **Severity:** Medium
- **Confidence:** High
- **Why it matters:** Operators get inconsistent tool outputs depending on which tool path they use.
- **Exact issue:** Integration layer defaults/paths around `app` conflict with newer app-scoped model and multi-app language in docs.
- **Exact fix direction:** Normalize all MCP log tools to same app enum (`hayalet-ev`, `mcp-server`), keep alias compatibility only at input parsing.

## 6) Noisy / duplicate / low-value logging areas

### Finding 15 — UI broadcast emits both batch and per-item events (duplicate traffic)
- **File path(s):**
  - `electron/logger/core/LoggerCore.ts`
- **Severity:** Medium
- **Confidence:** High
- **Why it matters:** Duplicated event fan-out increases renderer overhead and can create repeated UI entries.
- **Exact issue:** `flushUIBroadcastQueue()` sends `log:ui-notify-batch` and then loops to send `log:ui-notify` for each item.
- **Exact fix direction:** Choose one transport contract (prefer batch) and provide adapter in UI if single-event consumption is needed.

### Finding 16 — Console interception can amplify legacy noise into structured logs
- **File path(s):**
  - `src/js/modules/logger/Logger.ts`
  - `electron/logger/core/ConsoleInterceptor.ts`
- **Severity:** Medium
- **Confidence:** Medium
- **Why it matters:** High noise-to-signal ratio buries operationally useful events.
- **Exact issue:** Console overrides mirror every `console.*` into logs; preload and third-party scripts can generate substantial low-value volume.
- **Exact fix direction:** Apply category throttling/sampling for LEGACY logs and allow per-source suppression.

### Finding 17 — Some recoverable failures logged as errors, true blind spots logged as debug
- **File path(s):**
  - `src/js/pages/entrance/webview-panel.ts`
  - `src/js/modules/traffic-manager.ts`
- **Severity:** Medium
- **Confidence:** Medium
- **Why it matters:** Alerting quality degrades when severity does not reflect impact.
- **Exact issue:** Certain non-terminal webview console errors are elevated to error, while probe cycle failures and state cleanup failures are often debug only.
- **Exact fix direction:** Reclassify using explicit policy and add alerting tags (`recoverable`, `terminal`, `degraded`).

## 7) Priority hardening plan

### P0 (Immediate)
1. Canonicalize log root and app IDs (`hayalet-ev`, `mcp-server`), add backward-compatible read layer.
2. Unify session manager and schema; deprecate legacy manager.
3. Add trace propagation contract (`traceId/spanId`) across renderer ↔ electron ↔ MCP.
4. Eliminate empty catch blocks in critical lifecycle (preload setup, sync, relay, traffic).

### P1 (Short term)
1. Slot symmetry package: shared lifecycle instrumentation for ai0/ai1/ai2.
2. Severity policy matrix + lint checks for logger helper usage.
3. Replace localized persisted messages with stable event keys + params.

### P2 (Mid term)
1. Reduce duplicate UI broadcast path (batch-only transport).
2. Add noise controls (sampling/throttle) for console-derived LEGACY categories.
3. Extend retry/timeout/cleanup logs with consistent phase markers for replayable timelines.

---

## Recommended minimum schema (target)

Every structured event should include:

- `timestamp`
- `app` (`hayalet-ev|mcp-server`)
- `runtimeSource` (`renderer|main|preload|mcp-server`)
- `level`
- `category`
- `eventKey` (stable)
- `messageParams` (optional)
- `slot` (if applicable)
- `providerId` (if applicable)
- `sessionId`
- `conversationId` (if applicable)
- `traceId`
- `spanId`
- `correlationId` (compat)
- `visibility` (main app only)
- `error` object (for failures)

This schema would make major lifecycle transitions reconstructable and cross-system debugging materially more reliable.
